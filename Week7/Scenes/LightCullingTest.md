# Light Culling 테스트

## 사용 방법

1. 에디터의 씬 열기로 `Scenes/LightCullingTest.scene`을 연다. 현재 씬에 보존할 변경이 있으면 먼저 저장한다.
2. `Settings → Rendering → Light Culling`과 `Culling View`를 켠다.
3. `Frame Culling Test`를 누른다. 선택한 뷰를 테스트용 원근 카메라와 Solid/Phong으로 맞춘다. 씬 자체를 불러오거나 바꾸는 버튼은 아니다.
4. Culling View를 끄면 같은 시점의 일반 조명 결과를 볼 수 있다.

카메라 프리셋: 위치 `(-18, 0, 14)`, +X를 향하며 약 30도 아래를 보는 방향, FOV 60도, near 0.1 / far 200.

`Light Culling`은 기본 ON이며 `editor.ini`에 저장된다. OFF로 바꾸면 컬링용 깊이 패스와 Compute Shader를 생략하고 전체 포인트/스폿 라이트를 순회한다. `Culling View`는 디버그 표시만 켜는 별도 옵션이다.

## 씬 구성

외부 모델 없이 엔진 기본 Cube만 사용한다. 포인트 라이트 26개, 스폿 라이트 4개, 메시 6개다.

| 구성 | 목적 |
| --- | --- |
| 바닥과 뒷벽 | 넓은 깊이 표면에서 타일 경계를 관찰 |
| 높이와 깊이가 다른 블록 4개 | 앞뒤 평면이 다른 표면에서 목록이 달라지는지 관찰 |
| 격자 포인트 라이트 12개, 반경 4.5 | 서로 떨어진 영역과 겹치는 경계 비교 |
| `(6, 0, 2.2)` 주변 포인트 라이트 12개, 반경 4 | 중앙의 높은 라이트 개수 확인 |
| 아래를 향한 스폿 라이트 4개, 반경 7 | 통합 포인트/스폿 번호 및 조명 결과 확인 |
| `(80, 0, 4)`, `(0, 80, 4)` 포인트 라이트 2개, 반경 2 | 테스트 구조물에 닿지 않는 라이트가 목록에서 제외되는지 확인 |

JSON의 `TestCase`는 파일을 읽는 사람을 위한 설명이다. 현재 엔진은 이 필드를 액터 이름으로 사용하지 않는다.

## Culling View 표시

화면의 16×16픽셀 타일마다 실제 Compute Shader 출력의 라이트 개수를 색과 숫자로 표시한다. 포인트와 스폿의 합계이며, Ambient/Directional은 포함하지 않는다.

| 표시 | 의미 |
| --- | --- |
| 어두운 색 / 0 | 해당 타일에 저장된 라이트 없음. 배경만 있는 타일도 0 |
| 파랑 / 1 | 적은 라이트 |
| 청록 / 4 → 초록 / 8 → 노랑 / 16 | 겹치는 라이트 증가 |
| 빨강 / 32 이상 | 많은 라이트 |
| 자홍색 / 1024 | 목록 용량 도달. 일반 조명은 전체 라이트 순회로 돌아가 누락 방지 |
| 주황색 줄무늬 | 현재 뷰의 컬링 결과 없음: Light Culling 꺼짐, 직교, 와이어프레임, Draw Primitives 꺼짐 또는 생성 실패 |

디버그 표시 중에는 Fog, FXAA, 편집 오버레이를 건너뛰므로 타일 숫자가 흐려지지 않는다. Depth View와 동시에 켜면 Culling View가 우선한다. 디버그 토글은 세션용이며 editor.ini에 저장하지 않는다.

## 확인할 동작

- 중앙의 겹치는 라이트 영역에서 바깥쪽보다 숫자와 색 단계가 높아지는지 확인한다.
- `Light Culling`을 OFF/ON으로 전환해 조명 결과를 비교한다. OFF에서 `Culling View`는 주황 줄무늬, 다시 ON이면 현재 뷰의 타일 개수를 표시해야 한다.
- 카메라를 배경으로 돌리면 빈 타일은 0이 되어야 한다. 이전 카메라의 목록이 남으면 안 된다.
- 뷰포트 크기를 16의 배수가 아닌 크기로 바꿔도 오른쪽/아래쪽 부분 타일이 정상적으로 표시되어야 한다.
- Quad 뷰에서 직교 뷰는 주황 줄무늬이고, 원근 뷰는 자신의 결과를 표시해야 한다.
- Culling View를 끄고 Phong/Lambert에서 조명을 확인한다. 불투명은 타일 목록, 반투명 및 컬링을 생략한 뷰는 전체 라이트를 사용한다. Gouraud는 VS에서 전체 라이트를 계산한다.
- 스폿 컬링은 원뿔 대신 감쇠 반경의 구를 사용하므로, 화면의 개수는 실제 픽셀에 기여하는 조명보다 클 수 있다. 이 검사는 그림자 판정이 아니다.

## 검증 범위

C++ Debug 빌드와 CS / CullingView VS·PS / Phong PS의 개별 컴파일을 확인했다. 설치된 PDB 도구 문제를 피해 `/Z7`, 링크 디버그 정보 비활성화 설정으로 빌드했다.

GPU readback 및 씬 로딩 검증 프로그램은 준비했으나, 샌드박스 경로 접근 제한과 추가 실행 권한 미승인으로 완료하지 못했다. 실제 에디터 화면과 씬 로딩은 위 순서로 확인해야 한다.
